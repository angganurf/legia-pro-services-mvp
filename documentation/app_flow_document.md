# App Flow Document for Legia Pro Services MVP

## Onboarding and Sign-In/Sign-Up

When a new user arrives at the application, they first see the public landing page featuring the Legia logo, a navigation header, and an AI Assistant chatbox. From here, they can choose to sign up or sign in using the links in the header. Clicking on “Sign Up” opens a registration form that asks for the user’s email, password, full name, and role selection (Client or Professional). If the user is a Professional, they may optionally begin a KYC process by uploading identification documents during this step. After completing the form, they click “Create Account” and receive a verification email. Following the link in the email confirms their account and brings them to the sign-in page. Existing users choose “Sign In,” enter their email and password, and are redirected to the appropriate dashboard based on their role. If a user forgets their password, they click “Forgot Password,” enter their email, and receive a reset link. That link leads to a form where they set a new password and return to the sign-in screen. Signing out is accomplished by clicking the user avatar in the top right corner of any dashboard, choosing “Sign Out,” and being redirected back to the public landing page.

## Main Dashboard or Home Page

Once authenticated, every user lands on a dashboard tailored to their role. The dashboard layout shares a common structure: a collapsible sidebar on the left with navigation links, a top header showing the application logo, notification bell, and user avatar, and a main content area. Clients see links to “My Projects,” “AI Assistant,” “Orders,” and “Profile Settings.” Professionals see “Incoming Orders,” “My Work,” “Chat,” and “Profile Settings.” Admin users see “Admin Panel,” “User Management,” “Payment Settings,” and “System Logs.” The sidebar highlights the active section, and clicking any link loads that page in the main area. The header’s notification icon indicates new messages or order updates in real time. Users can collapse the sidebar to focus on content and expand it again when needed.

## Detailed Feature Flows and Page Transitions

### AI Project Creation and Matching Professionals

On the landing page or within the client dashboard under “AI Assistant,” a client can start a conversation with the Gemini-powered chatbox. They describe the kind of professional service they need, and the chatbox prompts follow-up questions. Once sufficient details are collected, the client clicks “Generate Project.” Behind the scenes, the frontend sends the entire conversation to `/api/projects/create-with-ai`. The API route uses the AI utility to analyze the input, create a new project record in the database, and generate sample images. It also runs a matching algorithm to find professionals who meet the project’s criteria. The API responds with the project summary, images, and a list of matched professionals. The client then sees a “Select Professionals” page where each professional appears in a card with their rate, rating, and location.

### Adding Professionals to Cart and Checkout

From the “Select Professionals” page, the client clicks on a professional’s card to open a detail modal. Inside the modal, they review the professional’s profile, view sample work, and choose a payment term plan. Clicking “Add to Cart” adds that professional to the client’s temporary order list. Once the client has added one or more professionals, they click “Proceed to Checkout” in the sidebar. This brings them to the “Checkout” page where project details and selected professionals appear in a summary table. Here the client reviews the milestones, total cost, and payment terms. Clicking “Confirm Order” triggers a call to `/api/orders` to create an order record. The API emits a `new_order` event over WebSockets to notify the chosen professionals. The client is then taken to an “Order Confirmation” page with order ID, details, and a button to view the order timeline.

### Professional Order Acceptance and Contract Review

When professionals log in, they see a red badge on “Incoming Orders” in the sidebar. Clicking that loads a list of new orders assigned to them. Each order shows the client name, project title, and due date. The professional clicks “View Order” to see the order details page, where they can accept or decline. Choosing “Accept Order” triggers an API call to `/api/orders/[orderId]/accept`, updates the order status, and sends a real-time notification to the client. The professional then reviews the contract terms, communicates any questions via the private chat room, and collaborates on refining milestones if needed. If no changes are needed, the professional clicks “Start Work” to move the order into the active state.

### Private Chat Between Client and Professional

Every order has a dedicated chat room accessible from the “Chat” link in the sidebar. Clicking “Chat” shows a list of active order rooms. Selecting a room opens the conversation view, where messages appear in chronological order. The input area supports typing text, attaching files, and sending emojis. Sending a message calls `/api/chat/send`, which stores the message and emits a WebSocket event to deliver it in real time to the other party. The chat view scrolls to the most recent message automatically, and unread messages yield a notification badge.

### Payment Workflow and Escrow Release

Payments occur in two phases according to the agreed-upon terms. After the professional accepts the order, the client is prompted to make the first milestone payment. They click “Make Payment,” which opens the integrated payment gateway flow (Xendit, Midtrans, or Tripay) in a modal. The client enters payment details, and the gateway returns a success or failure response via webhook to `/api/payments/webhook`. A successful payment updates the order status and releases the milestone amount from escrow to the professional. If a payment fails, the client sees an error message with a retry option. Once all milestones are complete and both parties confirm delivery, the client clicks “Release Final Payment.” That final transaction is processed in the same way, after which the order status changes to “Completed.”

### Admin Panel and User Management

Admins sign in like other users but are routed to the “Admin Panel” in the sidebar. The admin dashboard defaults to an overview of key metrics: total projects, active orders, pending KYC verifications, and recent payments. Admins click “User Management” to see a table of all users, filter by role or status, and approve or reject KYC documents. Selecting a user row opens a detail view where admins can update roles or reset passwords. Under “Payment Settings,” admins choose the active payment gateway, configure API keys, and set escrow rules. The “System Logs” section shows API call histories and error reports. All changes in the admin panel are handled via REST calls to `/api/admin/users`, `/api/admin/settings`, and so on, and they appear instantly because of WebSocket-driven notifications.

## Settings and Account Management

Every user has access to “Profile Settings” in the sidebar. This page displays personal information such as name, email, profile picture, and contact details. Users can edit any field inline and click “Save Changes” to update their profile. Professionals see an extra section for KYC status where they can upload or update identity documents. A separate “Security” tab allows changing the password by entering the current password and a new one. There is also a “Notifications” tab where users toggle email or in-app notifications for events like new messages or order updates. Saving preferences returns the user to the main settings overview. From any settings page, the user can click the application logo or the “Dashboard” link in the header to return to their role-based dashboard.

## Error States and Alternate Paths

If a user enters invalid credentials on the sign-in form, an error banner appears stating “Invalid email or password. Please try again.” After three failed attempts, the user is prompted to reset their password. During signup, if the email is already registered, the form displays “Email already in use” next to the email field. When a password reset token expires or is invalid, the reset form shows “Link expired. Request a new password reset.” In the AI Assistant flow, if the AI API returns an error, the chatbox displays “Something went wrong. Please try again.” Likewise, if WebSocket connectivity drops, the header displays a small offline indicator and retries the connection automatically. Payment failures trigger a modal that reads “Payment could not be processed. Please check your details or try a different method,” and the user can retry without losing the order state. If a user without proper role-based access tries to view a restricted page, they see a “403 – Unauthorized” screen with a button to navigate back to their dashboard.

## Conclusion and Overall App Journey

A user’s journey begins on the landing page where they chat with the AI to define a new project and then sign up for an account. After verifying their email, they sign in and land on a personalized dashboard. Clients proceed through AI-driven project creation, select professionals, and complete checkout, while professionals manage incoming orders, accept work, and collaborate via chat. Both parties move through payment milestones until the project is completed. Meanwhile, admins oversee the entire ecosystem through a dedicated panel for managing users, verifying KYC, and configuring payment gateways. Throughout, role-based navigation, real-time notifications, and clear error handling guide users smoothly from one step to the next, ensuring a coherent and efficient marketplace experience.
